# SSL/TLS Certificates

This directory contains self-signed SSL certificates for DogParkPals services.

## Certificate Files

### Application Services
- `server.crt` / `server.key` - Shared by the backend API and the frontend Nginx container for local HTTPS

### Observability Services
- `elasticsearch.crt` / `elasticsearch.key` - Generated by the stack script for Elasticsearch-related hardening work
- `rabbitmq.crt` / `rabbitmq.key` - RabbitMQ management interface and exporter trust chain

The current local Docker compose stack does not terminate HTTPS for Prometheus, Grafana, or Kibana, so there are no dedicated `prometheus`, `grafana`, or `kibana` certificates in active use.

## Generation

The stack script currently generates `server`, `elasticsearch`, and `rabbitmq` certificates automatically. To regenerate manually:

```bash
# For each service:
openssl req -x509 -newkey rsa:2048 -keyout SERVICE.key -out SERVICE.crt -days 365 -nodes -subj "/CN=SERVICE/O=DogParkPals/C=US"
```

Replace `SERVICE` with: server, elasticsearch, or rabbitmq.

## Security Notes

- **Development Only**: These are self-signed certificates for local development
- **Production**: Replace with properly signed certificates from a Certificate Authority (e.g., Let's Encrypt)
- **Validity**: 365 days from generation date
- **Gitignored**: All certificate files are excluded from version control for security

## File Permissions

- `.crt` files: 644 (readable by all)
- `.key` files: 600 (readable only by owner) - private keys must be protected

## Docker Usage

Certificates are mounted as read-only volumes in docker-compose.yml:
```yaml
volumes:
  - ./certs:/app/certs:ro
```

Additional mounts in the current stack:
- Frontend Nginx reads `server.crt` and `server.key` from `/etc/nginx/certs`
- RabbitMQ reads `rabbitmq.crt` and `rabbitmq.key` from `/etc/rabbitmq/certs`
- rabbitmq-exporter trusts `rabbitmq.crt` via `/etc/rabbitmq-exporter/ca.pem`
